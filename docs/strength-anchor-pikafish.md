# 绝对锚点：自研引擎 vs Pikafish（2026-09-24）

## 一句话

**Pikafish 每手只用 3 毫秒（单线程）就把自研引擎打到 4.2% 得分率，Elo −545。**
这不是「再训一个网络」能补的差距，是整个引擎工程的差距。

## 怎么测的

```bash
# A = 自研 JS 引擎（web/js/engine.js），每手 300ms
# B = Pikafish（trainer/engine/pikafish + pikafish.nnue），单线程
node tools/match.js --a js --b pika --ms-a 300 --ms-b 3  --games 24 \
    --openings 12 --open-plies 8 --random-plies 4 --max-ply 160 --jobs 6 \
    --gamelog /tmp/anchor-3.jsonl  --fresh
node tools/match.js --a js --b pika --ms-a 300 --ms-b 30 --games 24 \
    --openings 12 --open-plies 8 --random-plies 4 --max-ply 160 --jobs 6 \
    --gamelog /tmp/anchor-30.jsonl --fresh
```

`pika` 规格默认带 `EvalFile` / **`Threads: 1`** / `Hash: 128`。单线程是刻意的 ——
量的是「算法差距」，不是「核数差距」。

⚠️ `--depth` 是**全局**的（两边共用 `cfg.depth`），削弱对手只能靠逐方限时 `--ms-a` / `--ms-b`。

## 结果

| 对手每手 | 对手平均层数 | 我们平均层数 | 战绩 | 得分率 | Elo |
|---|---|---|---|---|---|
| **3 ms** | 18.8 | 6.04 | A 1 胜 0 和 23 负 | **4.2%** | **−545 [−900, −189]** |
| 30 ms | 38.7 | 5.78 | A 0 胜 0 和 24 负 | **0.0%** | 一边倒，算不出 |

- 独立起手局面 **12 组 / 24 局**（期望 12 组）✓ 成对设计完好
- **48 局全部以「将死」结束** —— 没有一局拖到和棋或手数上限
- 对比：8.9 倍数据量（472 万 → 4187 万唯一局面）带来的差距变化**是 0**；
  自研引擎自身的搜索改进（LMR + 空着 + 长将修复）值 **+76 Elo [+58, +94]**（1200 局）

## 为什么这个数字决定了方向

1. **对手用 1/100 的时间打穿我们。** 说明差距在搜索效率与评估速度，不是一个更聪明的评估函数。
2. **评估越贵，同预算搜得越浅，而层数才是这里的货币。** 1200 局 A/B 里 A 比 B 多 0.7 层 = +76 Elo；
   而网络接进引擎的实测代价是单节点 570 ns → 37.8 µs（**慢 66 倍**，同预算少搜 1.2 层）。
3. **5 项已被证伪的评估方向**：堆数据量、加大网络、换训练目标、加将位条件、网络接进引擎。
   唯一还有增量的「换特征族」也只是把线性探针的均势档相关系数从 0.3718 推到 0.3957
   （R² +27%），**是信息量下界，还没转成棋力**，且上界很低。

## 结论

- **棋力不要再往评估函数方向投入。** 要棋力就换引擎，或只做搜索侧。
- **分析 / 复盘 / 评估条** 是真正该用开源引擎的地方 —— 现在 app 的分析只有 depth 3~4。
- **陪练** 继续用自研引擎：`LEVELS` 的 `depth + slack`（在最优着法 N 分以内随机挑一手）
  是「像人一样让子」，开源引擎替代不了。

## 复现要点

- 想给出一个具体 Elo，对手得削弱到弱方**能捞到几局**；0% / 100% 的批次零方差，脚本只会报
  「一边倒」（`[0,0]` 那种假精度要当心）
- 这个口径下 Pikafish 与自研引擎都走 `tools/uci` 的同一套 UCI 协议，perft 1/2/3 已三方对数
  （44 / 1920 / 79666）
