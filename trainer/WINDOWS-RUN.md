# Windows 长跑 —— 操作说明

> 一键脚本：`win\run-full.bat`（双击即可，中途不用管）
>
> **支持断点恢复**：跑一半断电/自动更新重启，重新双击就接着上次的进度继续 ——
> 已完成的分片不会重做，时长累计计算，训练从最后完成的那个 epoch 续训。

---

## 一、拷什么过去

把整个 **`trainer\` 文件夹**拷到 Windows 上（覆盖旧的同名文件夹即可）。

| 目录 | 要不要拷 | 说明 |
|---|---|---|
| `src\` | **要** | 全部 .py，本次有更新（新增 `pipeline.py` 流程编排、`resume.py` 断点工具） |
| `tests\` | **要** | 评估脚本 + 断点测试 |
| `win\` | **要** | `run-full.bat` 已改成薄壳（调用 `src\pipeline.py`） |
| `README.md` `WINDOWS-RUN.md` | 要 | 文档 |
| `engine\` | **不用拷** | 你机器上那份 Pikafish exe + nnue 保留原地即可 |
| `data\` | **不要拷** | 旧的 3017 万条**重复率 84.3%**，不值得带过去（也省 2.6 GB） |
| `logs\` `results\` | **不要拷** | 重新训练会覆盖 |

> ⚠️ 旧的 `data\` 建议直接删掉腾空间 —— 那批数据用 `--opening-plies 6` 生成的，
> 唯一局面只有 472 万，留着也不会再用。新脚本写的是 `data\v2\`，不会碰它。

## 二、跑之前确认三件事

1. **磁盘留 20 GB 以上**（生成物 6~8 GB，训练时全量加载进内存，峰值约 2 倍）
2. **`engine\` 里有这两个文件**（同一层）：
   - `pikafish.exe`（或 `Pikafish-Windows-x86-64-universal.exe`）
   - `pikafish.nnue`（约 50 MB）
3. **torch 装的是 CUDA 版**（不是 CPU 版）。不确定就先双击 `win\0-fix-torch.bat`，
   再跑一次 `win\2-selfcheck.bat`

## 三、三种用法

```bat
run-full.bat            续跑：已完成的步骤自动跳过（默认用法）
run-full.bat --status   只看每一步做完没有，不跑任何东西（几秒）
run-full.bat --fresh    忽略全部断点，从头重跑
```

**参数改哪**：`src\pipeline.py` 顶部的 `CONFIG` 块（原来在 bat 里，现在挪到 Python 了）。
常见几个：

| 键 | 默认 | 说明 |
|---|---|---|
| `minutes` | 540 | **累计**生成时长 —— 跨重启累计，不是每次从头算 |
| `workers` | 14 | 按 CPU 核数设（8 核 16 线程的机器给 14 合适） |
| `opening_plies` | 14 | 开局随机步数，调小会让重复率飙升 |
| `epochs` | 8 | 训练轮数 |
| `l1` / `l2` | 512 / 64 | 网络宽度 |

## 四、九步分别做什么、大概多久

| 步骤 | 做什么 | 大概耗时 |
|---|---|---|
| 1 | 环境自检 | 10 秒 |
| 2 | **生成数据**（14 worker / 深度 8 / 开局随机 14 手） | **540 分钟** |
| 3 | 数据统计：记录数、**唯一局面数、重复率** | 1~3 分钟 |
| 4 | 训练（8 轮，512/64） | 20~40 分钟 |
| 5 | 导出 + 独立复现校验 | 10 秒 |
| 6 | 拟合报告 | 1 分钟 |
| 7 | **判断力评估（500 局面）** + 手写评估配对检验 | 10~15 分钟 |
| 8 | 汇总产物到 `results\` | 5 秒 |

**合计约 9.5~10 小时**，12 小时窗口内有富余。

## 五、断点恢复到底是怎么做的

**这是这次最该知道的部分。** 之前的情况是：只要 `data\v2\` 存在，脚本就会先提示
再 **`rd /s /q` 把整个目录删掉** —— 半夜 Windows 自动更新重启，9 小时的数据就没了。
现在不会了：

| 阶段 | 重启后 |
|---|---|
| **数据生成** | 读 `data\v2\_progress.json` 里的累计时长，**只补差额**；分片是追加写，已有数据一条不动 |
| 崩在半路的分片 | 启动时检查文件大小是不是 93 的整数倍，**把尾部那半条记录截掉**（不截的话后续 append 会让整个文件错位，而且训练时不会报错） |
| **训练** | 每个 epoch 结束都原子写 `logs\v2\ckpt.pt`（含模型 + 优化器 + 学习率调度 + 随机数状态），重启后**从下一个 epoch 继续** |
| 训练参数变了 | 如果 `--l1/--l2/--target-mode` 与 checkpoint 不一致，会**明确拒绝**并退出码 2（而不是悄悄接着训出一个四不像） |
| 数据变了 | 会打印警告说明「验证集指标与之前几轮不可比」，然后继续 |
| 导出/报告/评估 | 有产物文件就跳过 |

**旧数据没有时长记录怎么办**：如果 `data\v2\` 是旧版本生成的（没有 `_progress.json`），
脚本会按「记录数 ÷ 速率」**估算**已跑时长并明确标出（默认按 1500 条/秒）。
估算只是数量级上对，不符预期就调 `minutes`，或者删掉目录重来。

## 六、跑完把 `results\` 整个发回来

| 文件 | 是什么 |
|---|---|
| `xq-v2.xqnn` | **训练出的网络**（约 2.6 MB） |
| `train.log` | 完整训练日志（跨重启的都在同一个文件里） |
| `ckpt.pt` | checkpoint（可直接续训） |
| `01-dataset-info.txt` | 记录数 / 唯一局面数 / **重复率** |
| `02-export.txt` | 导出 + 独立复现校验结果 |
| `03-verify.txt` | 拟合报告 |
| `04-strength.txt` | **判断力评估**（名次 + 丢分） |
| `05-handcrafted.txt` | 与手写评估的配对检验 |
| `positions.json` | 局面与候选快照，便于复算 |

## 七、这次长跑要看什么

**只看两个数：**

1. `01-dataset-info.txt` 里的**重复率** —— 期望落在 30% 上下。
   如果又接近 80%，说明开局随机还不够，先把 `opening_plies` 再调大，别急着堆时长
2. `04/05` 里的**平均丢分**（选中着法比引擎首选差多少分）——
   比"平均名次"灵敏得多。详情见 `README.md` 第五节

**期望管理（重要）**：这次能把唯一局面数从 472 万推到 **4000~6000 万**，
是第一次进入"可能真的学到东西"的量级。但要清楚：

- 数据能提升的是**评估质量**，不会自动变成棋力
- 实测静态评估的丢分（约 50 分）比引擎 depth 1（6.5 分）差近 8 倍，
  而这 8 倍基本都来自**搜索**，不是评估
- **而且已经实测过**：把这批网络接进真引擎当评估函数，逐档位都**不会更强**，
  因为单节点成本涨 66 倍、时间受限下少搜约 1.2 层（见 `tools/net-in-engine/`）。
  真正的收益要等网络配合增量累加器和 SIMD、或者换更大的数据量之后才可能体现

**结论：值得跑，但别指望这一跑就能上场。** 它可以回答"数据量到底是不是瓶颈"
这个一直没被验证的问题 —— 这是目前最大的未知。

## 八、出问题怎么办

失败时脚本会停下并打印最常见的三种原因（引擎缺失 / torch 装成 CPU 版 / 磁盘不足）。

**修好之后直接重新双击 `run-full.bat` 就行** —— 已完成的步骤会跳过，
数据生成接着已有分片跑，训练从最后完成的 epoch 继续。**不要删 `data\` 目录。**

想看某一步的完整输出，直接看 `results\` 里对应的 `0X-*.txt`；
想确认每一步的状态，先跑 `run-full.bat --status`。
