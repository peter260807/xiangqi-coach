# 象棋 NNUE 训练包

用 Pikafish 的自对弈数据，训练一个**轻量的局面评估网络**，最终导出一个可以被引擎加载的网络文件。

一句话理解它在做什么：**让一个小网络去学会模仿 Pikafish 的判断**。
学成之后，把它接到自己的搜索引擎里，棋力就会明显强于手写的评估函数。

---

## 一、跑之前要准备两样东西

### 1. Python 3.10 或更高

下载：https://www.python.org/downloads/

安装时**务必勾选 "Add python.exe to PATH"**，否则命令行里找不到 `python` 命令。

### 2. Pikafish 引擎 + 神经网络权重

1. 打开 https://github.com/official-pikafish/Pikafish/releases
2. 下载最新那个 `Pikafish.YYYY-MM-DD.7z`（约 51 MB）
3. 解压，把下面两类文件复制到本目录的 `engine\` 文件夹：

| 包里的文件 | 放到哪里 | 说明 |
|---|---|---|
| `Pikafish-Windows-x86-64-universal.exe` | `engine\pikafish.exe` | 建议改名，方便脚本识别 |
| `pikafish.nnue` | `engine\pikafish.nnue` | 约 50 MB，**必须和 exe 放同一目录** |

> ⚠️ 注意从官方仓库 `official-pikafish/Pikafish` 下载。网上有不少仿冒站，
> 同一件事一会儿说基于 NNUE 一会儿说基于 MCTS，协议和版本号还互相矛盾。

## 二、怎么跑

> 📌 **脚本界面是英文的**（比如 `Step 3/5 - Generate training data`），这是刻意的。
>
> `.bat` 文件在中文 Windows 上会被 cmd 按 **GBK(936)** 解码。如果里面写中文，
> 而文件是 UTF-8 编码，轻则显示乱码，**重则因为乱码字节里出现特殊字符导致
> 脚本直接跑不起来**。注意 `chcp 65001` 救不了这个 —— 它只改控制台的**输出**，
> 不改 cmd **读取文件**用的编码。
>
> 所以约定是：**bat 只负责干活（纯英文），中文说明都写在本文档里，
> 而 Python 脚本输出的中文是正常的**（bat 里设了 `PYTHONIOENCODING=utf-8`）。

### 方式 A：分步跑（推荐第一次用）

按顺序双击，每步都有输出可以看：

| 脚本 | 做什么 | 大致耗时 |
|---|---|---|
| `win\1-install.bat` | 装 numpy 和 PyTorch **CUDA 版**（约 2.5 GB，走 PyTorch 官方索引） | 10~30 分钟（看网速） |
| `win\2-selfcheck.bat` | 环境自检，确认引擎和显卡都能用 | 10 秒 |
| `win\0-fix-torch.bat` | **只在 PyTorch 有问题时用**：自动区分「装错包 / 驱动太旧 / c10.dll 报错」并修复 | 5~15 分钟 |
| `win\3-gen-data.bat` | 生成训练数据 | **2~4 小时** |
| `win\4-train.bat` | 训练网络 | **1~3 小时** |
| `win\5-export-verify.bat` | 导出 + 验证效果 | 1~2 分钟 |

### 方式 B：无人值守

确认 `1-install.bat` 和 `2-selfcheck.bat` 都通过之后，直接双击 `win\run-all.bat`，
它会自动依次跑完数据生成 → 训练 → 导出验证。可以出门前点开，回来直接看结果。

## 三、参数怎么调

三个 `.bat` 文件的开头都有参数区，用记事本打开就能改。

### 数据生成（`3-gen-data.bat`）

```bat
set WORKERS=14      :: 并行进程数。5700X 是 8核16线程，14 比较合适
set DEPTH=8         :: 每步搜索深度。调大质量更高但更慢
set MINUTES=180     :: 跑多少分钟
```

**关于 DEPTH**（对最终效果影响最大的一个）：

| DEPTH | 相对速度 | 数据质量 | 建议 |
|---|---|---|---|
| 6 | 最快 | 一般 | 只想先跑通流程看看 |
| **8** | 基准 | 好 | **推荐起手** |
| 10 | 约慢一半 | 更好 | 时间充裕时用 |
| 12 | 约慢 4 倍 | 最好 | 数据量少时用来提质 |

> 有个坑要提醒：**别用 `movetime` 来限流**。它会让引擎把时间用满，
> 哪怕 2ms 就找到最优着法了。实测下同样的局面，
> `movetime 50` 测出来 20 局面/秒，`depth 8` 能到 468 局面/秒 —— **差 20 倍**。
> 这个包已经统一用 `depth`，不用你操心。

### 训练（`4-train.bat`）

```bat
set EPOCHS=8        :: 把数据过几遍
set BATCH=8192      :: 每批样本数。显存需求约 0.4 GB，8G 的卡也毫不吃力
set LR=0.001        :: 学习率
```

数据多的时候，`EPOCHS` 可以适当调小；数据少就调大。

### 换显卡了，参数要改吗

**基本不用改。** 这个项目对显卡要求很低，中端卡都能跑顺：

| | RTX 2080Ti | RTX 3060Ti |
|---|---|---|
| 架构 / 计算能力 | Turing / sm_75 | Ampere / sm_86 |
| FP32 算力 | 13.45 TFLOPS | **16.2 TFLOPS**（高 20%） |
| 显存 | 11 GB | 8 GB |
| 显存带宽 | 616 GB/s | 448 GB/s（低 27%） |
| CUDA 版本 | cu126 起 | cu126 起（同样支持） |

**为什么换卡几乎没感觉** —— 实测把训练的一步拆开（batch 8192）：

| 环节 | 占比 |
|---|---|
| CPU 侧：特征编码 + 取数 + 张量转换 | **约 35~40%** |
| GPU 侧：前向 + 反向 | 约 60~65% |

看着 GPU 占大头，但这个网络**只有 32 万参数**，对任何现代显卡都是小活。
真正决定吞吐的是 CPU 侧的特征编码和每批数据的搬运。于是：

- **数据生成阶段完全由 CPU 决定**，显卡一点忙都帮不上
  （Pikafish 官方 FAQ 明确写着不支持 GPU 推理）
- **训练阶段**两张卡的实际差距远小于纸面的 20%，因为瓶颈不在算力

**显存 8G 够不够？够，而且很宽裕。** 实测 batch 8192 的全部张量：

| 组成 | 占用 |
|---|---|
| 特征索引 (8192, 32) int64 | 2 MB |
| 各层激活 | 19 MB |
| 反向再存约两倍中间量 | 38 MB |
| PyTorch 运行时本身 | 约 300 MB |
| **合计** | **约 350 MB** |

8 GB 有 **20 倍以上裕度**，`BATCH` 不用调小。`2-selfcheck.bat` 会把你机器上的
实际显存和结论直接打出来，不用自己算。

**内存才是提升空间。** 数据集是**全量读进内存**的（1 亿局面约 9.3 GB），
内存宽裕就可以把 `MINUTES` 延长、生成更多数据 —— **数据量对最终效果的影响
远大于显卡**。

> 顺带一提：拼接分片时峰值内存约为数据量的两倍，所以 24 GB 以上比较稳妥。
> 自检里会一并报出来。

### 无人值守（`run-all.bat`）

参数分两段，一段管数据生成、一段管训练，含义相同。
默认配置按 8 核 16 线程 CPU 估算约 **5~8 小时** —— 显卡强弱对这个时长影响很小。

## 四、产出什么

跑完之后 `logs\` 目录里会有：

| 文件 | 是什么 |
|---|---|
| **`xq-v1.xqnn`** | **最终网络**（约 1.3 MB），引擎加载这个 |
| `weights.pt` | PyTorch 权重，可以继续训练 |
| `train.log` | 训练日志 |
| `data\part_*.bin` | 训练数据，确认没问题后可以删掉腾空间 |

### 网络文件格式

`xq-v1.xqnn` 是个简单的二进制文件（全部 little-endian）：

```
偏移   类型              内容
0      char[4]           魔数 "XQNN"
4      uint32            格式版本（1）
8      uint32            特征维度 feat_dim（1260）
12     uint32            第一层宽度 l1（256）
16     uint32            第二层宽度 l2（32）
20     uint32            保留
24     float32[l1][feat_dim]   第一层权重
...    float32[2][l1]          先后手偏置
...    float32[l2][l1]         第二层权重
...    float32[l2]             第二层偏置
...    float32[1][l2]          第三层权重
...    float32[1]              第三层偏置
```

引擎侧照着这个写推理就行：

```
acc[i] = Σ feat_weight[i][f] + side_bias[side][i]   // f 是该局面的激活特征
h1[i]  = clamp(acc[i], 0, 1)
h2[j]  = clamp(Σ fc2_weight[j][i] * h1[i] + fc2_bias[j], 0, 1)
logit  = Σ fc3_weight[0][j] * h2[j] + fc3_bias[0]
prob   = sigmoid(logit)                              // 走子方胜率
cp     = 400 * ln(prob / (1 - prob))                 // 换算成引擎惯用的分值
```

**特征怎么编码**（这一步必须两端一致，否则网络等于废的）：

- 棋盘按 `r * 9 + c` 编号，`r=0` 是黑方底线（对应 UCI 的行 9），`r=9` 是红方底线
- 每个有子的格子产生一个特征，索引 = `格子编号 * 14 + 类型编号`
- 类型编号**跟走子方有关**：轮到谁走，谁的子就是 `0-6`（帅仕相马车炮兵），对方是 `7-13`
- 一共 `90 * 14 = 1260` 维

视角归一化这一步很关键：轮红方走和轮黑方走，同一个棋盘的编码是不同的。
这样网络只需要学一套「己方 / 对方」的概念，不必为红黑各学一套，样本效率翻倍。

## 五、怎么看结果

`5-export-verify.bat` 最后会打出一份验证报告，重点看这几个数：

```
  与引擎评分的相关系数 : 0.85      ← 最重要，越接近 1 越好
  换算成引擎分值：平均偏差 68.1 分  ← 一个兵约 100 分，可以拿这个当尺子
```

- **相关系数 0.8 以上**：网络确实学到了引擎的判断，可以用了
- **0.6~0.8**：学到了大方向，但还不够
- **0.6 以下**：数据太少或训练不够，加数据或加轮次

报告最后还会抽样打印几个具体局面，把棋盘、引擎评分、网络预测并排显示，
可以直接肉眼核对网络判断得靠不靠谱。

## 六、常见问题

**Q：`2-selfcheck.bat` 说找不到引擎**
把 `pikafish*.exe` 和 `pikafish.nnue` 放进本目录的 `engine\` 文件夹，两者必须在同一层。

**Q：引擎启动失败 / 权重加载不了**
多半是 exe 和 nnue 版本不匹配。用同一个发布包里的这两个文件，
别把不同版本混着用。可以在命令行手动跑一次 exe，它会打印具体原因。

**Q：`torch\lib\c10.dll` 初始化失败（WinError 1114）**

这是 Windows 上最常见的 PyTorch 问题。按可能性从高到低：

1. **PyTorch 2.9.x 本身有这个 bug** —— 多人反馈回退到 2.8.0 就好了。
   `1-install.bat` 已经锁定 2.8.0；如果你之前手动装过别的版本，
   跑一次 `0-fix-torch.bat` 会自动处理。
2. **缺少 Visual C++ 运行库** —— 下载安装（注意要 x64 那个）：
   https://aka.ms/vs/17/release/vc_redist.x64.exe
   装完**重启电脑**再试。
3. **装了 CUDA 版但机器环境不匹配** —— 可以先装 CPU 版把整个流程跑通，
   确认脚本没问题了再换 CUDA 版。

`0-fix-torch.bat` 会按这个顺序自动排查一遍，不用手工折腾。

**Q：自检说装的是 CPU 版 PyTorch / CUDA 不可用** ⚠️ 最容易踩的坑

**PyPI 上 Windows 的 torch 轮子是纯 CPU 版**（230 MB；同版本 Linux 轮子 847 MB
才含 CUDA）。所以 `pip install torch` 会**安装成功、看起来一切正常，但显卡永远用不上**，
`torch.cuda.is_available()` 一直是 `False`——不报错，只是慢。

必须指定 PyTorch 自己的索引：

```
pip uninstall -y torch
pip install "torch==2.8.0" --index-url https://download.pytorch.org/whl/cu126
```

⚠️ 那句 `uninstall` 不能省。已装的 CPU 版版本号就是 `2.8.0`，pip 认为
`torch==2.8.0` 已经满足，**不会重新下载**，你会一直停在 CPU 版上。

怎么判断是哪种情况，看自检输出里的「CUDA 标记」：

| 自检显示 | 含义 | 怎么办 |
|---|---|---|
| `CUDA 标记：无` | 装的是 CPU 版，与驱动无关 | 按上面两条命令重装 |
| `CUDA 标记：12.6` 但仍不可用 | 包对了，**驱动太旧** | `nvidia-smi` 看版本，低于 527 就去 nvidia.com 更新驱动 |

CUDA 版本与驱动的最低要求：`cu126` 要 527+，`cu128` 要 570+，`cu129` 要 575+。
2080Ti 是 Turing（sm_75），这三个都还支持。想换版本就打开 `win\1-install.bat`
改 `CUDA_INDEX` 那一行。

**Q：磁盘不够**
1 亿个局面约占 9.3 GB。跑之前留 30 GB 比较稳妥。
数据用完（训练结束后）可以删掉 `data\` 腾空间。

**Q：训练到一半想停**
按 Ctrl+C 就行，每轮结束都会存 checkpoint，已训练的进度不会丢。
想接着训就把 `EPOCHS` 调大重跑，它会从头开始 —— 如果要严格续训，
需要改 `train.py` 加加载 checkpoint 的逻辑。

**Q：数据生成阶段某个 worker 报"引擎异常，重启"**
不影响，脚本会自动重启那个 worker 继续跑，最后会统计异常次数。
偶尔一两次正常，如果频繁出现就要检查机器是不是过热或内存不足。
